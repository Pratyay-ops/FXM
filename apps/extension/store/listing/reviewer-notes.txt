FXM Connect: notes for store reviewers

WHAT IT IS
FXM Connect is the companion extension of the FXM web app, a free and open-source music player at https://fxmusic.pages.dev/app/ (source code: https://github.com/Pratyay-ops/FXM, Apache-2.0). FXM has no servers: the web app runs entirely in the browser, and FXM Connect lets it reach the music services it plays from. The extension has no user interface besides its options page.

WHAT IT DOES
1. Static declarativeNetRequest rules (rules.json, shipped with the extension). They apply only to requests initiated by https://fxmusic.pages.dev (initiatorDomains, plus the exact host permission for that origin). They set Origin and Referer on requests to YouTube's API hosts and to open.spotify.com's token and server-time endpoints and clienttoken.spotify.com; add Access-Control-Allow-Origin (the exact FXM origin, never *) and related CORS headers to the answers of YouTube, googlevideo, Spotify's web-player APIs and Last.fm's station JSON; and remove Cookie, Set-Cookie and Access-Control-Allow-Credentials. There is no webRequest permission.
2. A content script on https://fxmusic.pages.dev only. It marks the page (data-fxm-connect on the html element) and answers a ping, so the web app knows the extension is installed.
3. Always on, without cookies: when the FXM page asks, the background relays GET https://open.spotify.com/api/server-time (credentials: 'omit') and returns only the HTTP status and the JSON body. Spotify's web-player tokens need its server time. This needs no setting, also works in private windows, and counts toward the rate limit of item 4.
4. An optional Spotify login bridge, off by default (the options page toggle "Use my Spotify login from this browser"). While it is on, the FXM page can ask the background for a Spotify web-player token: the background makes one GET request to https://open.spotify.com/api/token with allow-listed query parameters and credentials: 'include', and returns only the HTTP status and the JSON body to the page. It never reads cookies (there is no cookies permission), refuses pages in private windows and container tabs, serves at most 10 requests a minute together with item 3, and keeps the toggle in the extension's own IndexedDB, out of content scripts' reach. In Firefox, turning the toggle on first requests the optional data collection permission authenticationInfo (permissions.request), and the background serves tokens only while Firefox reports it as granted. The web app's option to connect a Spotify account, which uses this bridge, comes in a later FXM release: until then, turning the toggle on changes nothing visible in the web app.

DATA COLLECTION
Nothing goes to the developer: no analytics, no telemetry, no servers. The web app's requests go straight to the services the user uses. The only personal data the extension handles is the user's Spotify access token, and only with the login bridge on: the token comes from open.spotify.com, requested with the browser's own cookies for that site, and goes to the FXM page in the same browser, which uses it only for its requests to Spotify. The Firefox manifest therefore declares data_collection_permissions with required: ["none"] and optional: ["authenticationInfo"], and the Edge listing declares authentication information.

HOW TO TEST
1. Install the extension, then open https://fxmusic.pages.dev/app/. No account is needed.
2. The page's html element gets a data-fxm-connect attribute holding the extension's version.
3. Search for a song in the web app, with the browser's developer tools open on the Network tab. With the extension, the answers from YouTube Music and Spotify carry Access-Control-Allow-Origin: https://fxmusic.pages.dev. Without it they don't: Spotify is unreachable, and YouTube Music works only in the web app's experimental no-install mode, where the browser allows that.
4. Open the extension's options page: it shows the version, the allowed FXM page and the Spotify toggle, which is off. In Firefox, turning the toggle on shows Firefox's prompt for authentication information.

BUILDING FROM SOURCE
The scripts background.js, content.js and options.js are built with Vite from the TypeScript in apps/extension/src, without minification; manifest.json and rules.json are generated from apps/extension/src/manifest.ts and rules.ts, and the icons are drawn by apps/extension/scripts/icons.ts. The source archive is the whole FXM repository at the release's commit.

Requirements: Linux or macOS with Node.js 22 (22.13 or later: the repository's engines field refuses Node 24), git, curl, tar, openssl and access to the npm registry.

1. Unpack the archive and open a terminal in its top folder.
2. Run: scripts/setup.sh --frozen-lockfile --filter @fxm/extension
   This installs pnpm 12.12.1 into .tools/bin (checked against its npm integrity hash), then the extension's dependencies exactly as pnpm-lock.yaml pins them.
3. Run: scripts/run.sh pnpm --filter @fxm/extension build
4. The Firefox build is in apps/extension/dist/firefox/ and the Chromium build in apps/extension/dist/chromium/. Their files match the extension's files.

These notes are also in the archive, in apps/extension/store/listing/reviewer-notes.txt.

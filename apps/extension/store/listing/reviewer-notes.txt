FXM Connect: notes for store reviewers

WHAT IT IS
FXM Connect is the companion extension of the FXM web app, a free and open-source music player at https://fxmusic.pages.dev/app/ (source code: https://github.com/Pratyay-ops/FXM, Apache-2.0). FXM has no servers: the web app runs entirely in the browser, and FXM Connect lets it reach the music services it plays from. The extension has no user interface besides its options page.

WHAT IT DOES
1. Static declarativeNetRequest rules (rules.json, shipped with the extension). They apply only to requests initiated by https://fxmusic.pages.dev (initiatorDomains, plus the exact host permission for that origin). They set Origin and Referer on requests to YouTube's API hosts and to open.spotify.com's token and server-time endpoints; add Access-Control-Allow-Origin (the exact FXM origin; * only on googlevideo's media answers to requests from that origin, because after googlevideo redirects a request to another host the browser sends Origin: null, and credentials are never allowed) and related CORS headers to the answers of YouTube, googlevideo, Spotify's web-player APIs and Last.fm's station JSON; and remove Cookie, Set-Cookie and Access-Control-Allow-Credentials. There is no webRequest permission.
2. A content script on https://fxmusic.pages.dev only. It marks the page (data-fxm-connect on the html element) and answers a ping, so the web app knows the extension is installed.
3. Always on, without cookies: when the FXM page asks, the background relays GET https://open.spotify.com/api/server-time (credentials: 'omit') and returns only the HTTP status and the JSON body. Spotify's web-player tokens need its server time. This needs no setting, also works in private windows, and counts toward the rate limit of item 4.
4. An optional Spotify login bridge, off by default (the options page toggle "Use my Spotify login from this browser"). While it is on, the FXM page can ask the background for a Spotify web-player token: the background makes one GET request to https://open.spotify.com/api/token with allow-listed query parameters and credentials: 'include', and returns only the HTTP status and the JSON body to the page. It never reads cookies (there is no cookies permission), refuses pages in private windows and container tabs, serves at most 10 requests a minute together with item 3, and keeps the toggle in the extension's own IndexedDB, out of content scripts' reach. In Firefox, turning the toggle on first requests the optional data collection permission authenticationInfo (permissions.request), and the background serves tokens only while Firefox reports it as granted. The web app's Settings, Spotify account section, uses this bridge for an experimental, opt-in account sync (tested against a stand-in for Spotify, not yet with real accounts): after the user accepts its notice there, the web app syncs the account's liked songs, playlists and Spotify home into the user's library on the device, read-only. If the user also turned on the web app's library sync, the copies of the liked songs and playlists go to the user's own secret GitHub gist with the rest of the library, as the notice says. Without the toggle on, the web app says how to turn it on and uses no account.

5. An optional YouTube Music library bridge, off by default (the options page toggle "Use my YouTube Music login from this browser"). It requires the user to grant the optional `cookies` permission and, in Firefox, the optional `authenticationInfo` data-collection consent. The background reads the normal-profile `music.youtube.com` cookies using the browser cookie API, only after the setting, permission and consent checks pass. It passes the cookie header in memory to the bundled `youtubei.js` Music client for authenticated, fixed YouTube Music InnerTube library reads. The page cannot supply a cookie, URL or arbitrary payload. It receives normalized metadata for Liked Music, library playlists, saved albums and followed artists plus a one-way account fingerprint. The cookie is never returned to the page, persisted by FXM, logged or sent to an FXM server. The bridge refuses private/incognito windows and Firefox container tabs. Turning off the option removes the optional `cookies` permission. The interface is unofficial and experimental.

DATA COLLECTION
Nothing goes to the developer: no analytics, no telemetry, no servers. The web app's requests go straight to the services the user uses. The extension handles account data only after explicit, independent opt-ins. The Spotify bridge passes the user's Spotify token to the FXM page in the same browser. The YouTube Music bridge reads the normal-profile music.youtube.com cookies in the background under the optional cookies permission and uses them in memory for authenticated YouTube Music reads; the browser sends them to YouTube with those requests. They are never returned to the page, persisted by FXM, logged or sent to an FXM server. Only normalized music metadata is returned to the page. The Firefox manifest therefore declares data_collection_permissions with required: ["none"] and optional: ["authenticationInfo"], and the Edge listing declares authentication information. Firefox's YouTube Music option additionally requests the optional cookies permission at the user's click.

HOW TO TEST
1. Install the extension, then open https://fxmusic.pages.dev/app/. No account is needed.
2. The page's html element gets a data-fxm-connect attribute holding the extension's version.
3. Search for a song in the web app, with the browser's developer tools open on the Network tab. With the extension, the answers from YouTube Music and Spotify carry Access-Control-Allow-Origin: https://fxmusic.pages.dev. Without it they don't: Spotify is unreachable, and YouTube Music works only in the web app's experimental Lite tier, which needs no install, where the browser allows it.
4. Open the extension's options page: it shows the version, the allowed FXM page and the independent Spotify and YouTube Music toggles, both off by default. In Firefox, turning the toggle on shows Firefox's prompt for authentication information.
5. Optional, with a Spotify account: sign in at https://open.spotify.com, turn the toggle on, then in the web app open Settings and select Connect your account in the Spotify account section. After its notice, the web app shows the account's name and adds copies of its liked songs and playlists to the library. Disconnect in the same section forgets the token. The account sync is experimental: it has been tested against a stand-in for Spotify, not yet with real accounts. If Spotify answers in a way this version of FXM can't read, Settings says so, and no copy in the library is emptied.

BUILDING FROM SOURCE
The scripts background.js, content.js and options.js are built with Vite from the TypeScript in apps/extension/src, without minification; manifest.json and rules.json are generated from apps/extension/src/manifest.ts and rules.ts, and the icons are drawn by apps/extension/scripts/icons.ts. The source archive is the whole FXM repository at the release's commit.

Requirements: Linux or macOS with Node.js 22 (22.13 or later: the repository's engines field refuses Node 24), git, curl, tar, openssl and access to the npm registry.

1. Unpack the archive and open a terminal in its top folder.
2. Run: scripts/setup.sh --frozen-lockfile --filter @fxm/extension
   This installs pnpm 12.12.1 into .tools/bin (checked against its npm integrity hash), then the extension's dependencies exactly as pnpm-lock.yaml pins them.
3. Run: scripts/run.sh pnpm --filter @fxm/extension build
4. The Firefox build is in apps/extension/dist/firefox/ and the Chromium build in apps/extension/dist/chromium/. Their files match the extension's files.

These notes are also in the archive, in apps/extension/store/listing/reviewer-notes.txt.

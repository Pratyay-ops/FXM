# @fxm/desktop

The FXM desktop app for macOS, Windows and Linux: the web app (`apps/web`) in a [Tauri 2](https://v2.tauri.app) shell. This is FXM's installable "applet". Stage 7.2 adds native networking through tauri-plugin-http, so YouTube and Spotify will work without the FXM Connect extension. This stage (7.1) builds the **shell** only.

Setup, prerequisites per OS, commands and disk usage are in [DEVELOPMENT.md → Desktop app](../../docs/DEVELOPMENT.md#desktop-app). In short:

```sh
make desktop-setup   # pinned Rust into .tools/, plus dependencies
make desktop-dev     # web dev server on port 5260 + the app window, with hot reload
make desktop-build   # FXM.app on macOS (all bundle types elsewhere), in src-tauri/target/release/bundle/
make desktop-check   # rustfmt, clippy, cargo test
```

## Layout

```
assets/icon.svg           the FXM mark (same art as the web favicon), source of every icon
scripts/prune-icons.mjs   keeps only the icons tauri.conf.json lists (run by the "icons" script)
test/                     Vitest checks of the Tauri config and desktop.yml; part of `make test`, no Rust needed
src-tauri/
  Cargo.toml, Cargo.lock  the Rust crate `fxm` (also the executable's name)
  rust-toolchain.toml     the pinned Rust release
  build.rs                tauri-build: capabilities, icons and the config for the macros
  src/main.rs, src/lib.rs plugin wiring and window handling (`run()`)
  tauri.conf.json         app identity, window, CSP, build commands and bundle settings
  capabilities/           what the web app may call: the http allow-list lives here
  icons/                  generated by `tauri icon`, committed
```

## How it works

- **Frontend.** `tauri build` runs `pnpm --filter @fxm/web build:desktop`, which builds the web app with base `/` into `apps/web/dist-desktop`. Tauri embeds that folder in the executable and serves it from `tauri://localhost` (`http://tauri.localhost` on Windows). The router takes its basename from `import.meta.env.BASE_URL`, so nothing in the web app changes. Unknown paths fall back to `index.html`, so reloading a deep link works.
- **Development.** `make desktop-dev` starts Vite with `--base=/ --port 5260 --strictPort` and points the window at `http://localhost:5260`. Release-only behaviour, the CSP in particular, needs `make desktop-build`.
- **Window.** One window labelled `main`: 1200×800, at least 360×600, titled FXM, with the dark theme's background (`#0b0b0f`) until the page paints. tauri-plugin-window-state restores its size, position, maximized and full-screen state, but never starts it hidden. tauri-plugin-single-instance brings it to the front when FXM is launched a second time. `dragDropEnabled: false` leaves drag and drop to the page, as in a browser: Tauri's native file-drop handling would turn off HTML5 drag and drop on Windows, which playlist reordering may rely on.
- **Links.** tauri-plugin-opener opens `target="_blank"` links in the default browser.
- **Network.** tauri-plugin-http is built with the `unsafe-headers` feature, which lets a request set headers such as `Origin` (youtubei.js needs it). Its scope in `capabilities/default.json` allows HTTPS requests only to YouTube, googlevideo, Spotify, LRCLIB, MusicBrainz, ListenBrainz, Last.fm, Internet Archive and Jamendo. The tests in `test/` pin that list, the permissions around it, `default.json` as the only capability file and the plugins `src/lib.rs` registers, so widening any of them is always a deliberate change.
- **No cookie jar.** The plugin's default `cookies` feature is off. It would save every response cookie in plain text in `.cookies` in the app's cache folder and send it back with later requests. youtubei.js doesn't need it, and stage 7.4 decides how Spotify credentials are stored.
- **No updater yet.** Stage 7.5 adds the updater, installers on GitHub Releases and macOS signing.

### Content security policy

```
default-src 'self'; img-src 'self' https: data: blob:; media-src 'self' https: blob:;
connect-src ipc: http://ipc.localhost 'self' https:; script-src 'self' 'wasm-unsafe-eval' blob:;
style-src 'self' 'unsafe-inline'
```

- `ipc:` and `http://ipc.localhost` carry Tauri's IPC (macOS and Linux, then Windows).
- At build time Tauri adds the SHA-256 hash of every inline script to `script-src`, so the theme script in `apps/web/index.html` keeps running.
- `blob:` in `script-src` lets the app run the signed YouTube resolver module it downloads from FXM's site (stage 1.13): the module's bytes are checked against their Ed25519 signature first, then loaded from a `blob:` URL made from exactly those bytes, which is revoked once loaded. It also lets the page run its other `blob:` URLs (artwork, audio) as scripts, which would matter only together with an injected `<script>` element naming one. The web app's own policy has no `blob:` there: it gets new code by redeploy. See [packages/platform/src/updates](../../packages/platform/src/updates/README.md).
- **No `'unsafe-eval'`.** Stage 7.2 doesn't add it: YouTube deciphering runs in a separate, hidden evaluator webview with its own policy (stage 1.11). Only if that webview can't work may 1.11 add `'unsafe-eval'` here, with the reason recorded in this README.

## Maintenance

**Icons.** Edit `assets/icon.svg`, then run `scripts/run.sh pnpm --filter @fxm/desktop icons` from the repo root. The mark sits on the macOS icon grid (an 824 px body on a 1024 px canvas), so it lines up with other apps in the Dock. `tauri icon` writes the entries of `icon.icns` in a different order on every run, so that file shows up as changed even when the art didn't.

**Versions.** Every pin follows the repo's 14-day rule (see [DEVELOPMENT.md](../../docs/DEVELOPMENT.md)):

| What | Pinned in | Notes |
|---|---|---|
| Rust | `src-tauri/rust-toolchain.toml` | 1.98.1. 1.99.0 miscompiles FFI `bool` returns on x86_64 ([rust-lang/rust#163911](https://github.com/rust-lang/rust/issues/163911)), and the fixed 1.99.1 is too new |
| rustup | `scripts/install-rust.sh` | Version plus one SHA-256 per platform, from `https://static.rust-lang.org/rustup/archive/<version>/<target>/rustup-init.sha256` |
| Crates | `src-tauri/Cargo.lock` | See below |
| `@tauri-apps/cli`, `@tauri-apps/api` | `package.json` | pnpm's `minimumReleaseAge` applies. Keep `@tauri-apps/api` on the same minor version as the `tauri` crate: `tauri build` refuses mismatched versions |

Cargo has no stable equivalent of pnpm's `minimumReleaseAge`, so re-resolve the whole lockfile with a publish-date cutoff 14 days back:

```sh
cd apps/desktop/src-tauri
cutoff=$(node -p 'new Date(Date.now() - 14 * 864e5).toISOString().slice(0, 19) + "Z"')
RUSTC_BOOTSTRAP=1 ../../../scripts/run.sh cargo generate-lockfile -Zunstable-options --publish-time "$cutoff"
```

`RUSTC_BOOTSTRAP=1` unlocks Cargo's unstable `--publish-time` flag for this one command, which only resolves versions and compiles nothing. Builds always use `--locked` in CI.
